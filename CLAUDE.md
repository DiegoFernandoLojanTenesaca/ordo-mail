# Ordo: internal guide

## Architecture

- `engine/` owns all logic. Modules: `config` (constants), `model` (types sent to the UI), `settings` (storage paths, keychain secrets, user settings, catalog), `error` (error codes), `auth` (OAuth), `gmail` (HTTP client, retries, batching, parallel reads), `rules` (filters are the rules), `ai` (providers, keys, models, JSON completions), `classifier` (prompt, batches and validation), `organize`, `subscriptions` (scan and unsubscribe), `cleanup`, `text`.
- `app/src-tauri/src/lib.rs` exposes one thin command per engine function and registers the updater and process plugins; no logic lives there.
- `app/src/lib/api.ts` is the only door to the engine; `store.svelte.ts` holds global state; `config.ts` holds UI registries (navigation, actions, stats, tabs); `theme.css` holds every token; `icons.ts` lists the Material Symbols in use; `i18n.svelte.ts` loads every locale folder.

## Hard rules

- Code, identifiers, keys and diagnostics in English. No comments.
- Gmail filters are the single source of truth for rules; never keep a local copy.
- The engine returns error codes and progress phases, never user text. The UI renders `t('errors:<code>')` and `t('progress:<phase>')`.
- UI text only through locale files, camelCase keys per feature namespace, plurals with `_one` / `_other` and `{count}`.
- Colors, sizes, spacing and type only from `theme.css` tokens, light and dark.
- TypeScript types in `app/src/lib/bindings` are generated by ts-rs; never edit them.
- Deleting mail means the Gmail trash, never permanent deletion. Protected labels are excluded from clean up.
- AI output is validated in `classifier.rs` before it can reach a filter or a search query. AI settings (model, address) are validated in `ai.rs`.
- Unsubscribe links come only from Gmail headers; one click POSTs go only to public https hosts (`text::safe_web_url`).
- No secrets in the repo. The refresh token and AI keys live in the OS keychain and are never returned to the UI.

## How to extend

- **Command**: engine function => `#[tauri::command]` in `lib.rs` => entry in `api.ts` => UI.
- **Type**: add `#[derive(TS)] #[ts(export)]` in the engine and run `cargo test -p engine`.
- **Language**: copy `app/src/lib/locales/en` to a new folder and translate; no code change.
- **Icon**: add its name to `app/src/lib/icons.ts`.
- **Setting**: field in `Settings` (engine) => row in `routes/settings` => keys in `locales/*/settings.json`.
- **AI provider**: variant in `ai::Provider` (URL, batch size, key) => adapter in `Client::complete_json` if it is not OpenAI compatible => `settings:providers.<name>` keys => link in `PROVIDER_LINKS` and the opener capability.

## Verify

- `cargo test -p engine` (unit tests and bindings) and `pnpm check` in `app`.
- `cargo test -p engine -- --ignored` runs Claude Code live and a read only smoke pass over the real mailbox (including a subscriptions scan).
- Run the devkit scans (hardcoded values, spacing, duplication, format) before committing.
- Commits: conventional, short, lowercase, no attribution footer.

## Release

- The version lives only in `app/package.json`.
- Bump it, replace `CHANGELOG.md` with the changes since the last release, commit, then push a tag with the same number (`0.4.0`, no `v`).
- The tag runs `.github/workflows/release.yml`: checks, builds and signs `ordo-<tag>.exe`, writes `latest.json` with `scripts/latest.mjs` and publishes both with the changelog. Nothing runs on plain pushes.
- The updater key lives in `~/.tauri/ordo.key` (password next to it) and in the repo secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Losing it means installed copies can no longer update themselves.
